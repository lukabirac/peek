Peek

Links open in a preview layer instead of taking over your tab. Close it and nothing changed; promote it and it becomes a real tab.

Triggers

Always peek links on these sites One hostname per line. Subdomains are included. Treats the site like a pinned tab even when it isn't one.

Split

Aside and recent Chromium both ship a real side-by-side split, but no extension can start one: splitViewId is exposed read-only, and the calls that create a split live in private namespaces reserved for the browser's own components. The side panel is the closest surface an extension is actually allowed to use.

One consequence worth knowing: the panel can't relax framing headers the way a Peek can, because those rules don't apply to requests an extension page starts. A site that refuses to be framed will offer you a tab instead of loading there.

How sites get embedded

Many sites send X-Frame-Options or a CSP frame-ancestors rule to stop themselves being framed. Peek suspends those headers so the preview can load — but only on the one tab holding the Peek, only for the frame itself, and only from the moment you press the link until the Peek closes. Nothing is relaxed globally or persistently.

The header API can drop a header but not rewrite one, so the site's whole Content-Security-Policy is suspended for that window rather than just its framing clause. That is the one real security trade-off in this extension, and it is why the arming window is kept as short as it is.
